# Marketing Quest

마케팅 교육을 위한 태블릿 중심 다크 UI 시뮬레이션입니다. 비즈니스와 상품을 별도로 생성하고, 미디어 믹스 → AARRR → 매출과 브랜드 변화의 관계를 실험합니다. React + TypeScript + Vite + Express를 사용합니다. DB, 외부 AI API 키는 필요하지 않습니다.

## 실행

```sh
npm install
cp .env.example .env.local
npm run dev
```

기본 포트는 3000입니다. 현재 작업 환경의 `.env.local`은 `PORT=3100`, 테스트용 `OPEN_STAGE=4`를 사용합니다. 사용 중인 포트는 `PORT=3104 npm run dev`처럼 변경할 수 있습니다. 브라우저 기록은 주소와 포트별로 분리됩니다.

```sh
npm test
npm run build
npm start
```

Node.js 22 이상을 사용하세요. 배포는 `npm ci && npm run build` 후 `npm start`로 실행하는 Node.js 호스팅 또는 아래 Vercel 구성을 사용합니다. 정적 파일만 배포하면 설정/실행 API가 동작하지 않습니다.

## Vercel 배포

`vercel.json`은 Vite 프런트엔드와 `api/session.mjs`, `api/simulate.mjs`, `api/replay.mjs` Node 함수를 함께 배포합니다. 로컬 Express와 서버리스 함수는 `simulation.mjs`·`model.mjs`의 같은 검증·계산을 사용하며 DB나 서버 저장소는 사용하지 않습니다. 브라우저 화면 경로는 `/` 하나이며 메뉴 상태는 브라우저 저장소에 보관합니다.

Vercel 프로젝트에 `OPEN_STAGE=4`, `WORKSHOP_ID=marketing-2026`, `WORKSHOP_NAME=마케팅 전략 실전 워크숍`을 설정하면 테스트용으로 전체 단계가 열립니다. 운영 시 `OPEN_STAGE`를 바꾸고 재배포한 뒤 참가자가 새로고침합니다. 원본 신청 CSV, `.env*`, 로컬 결과·스크린샷은 `.vercelignore`로 업로드하지 않습니다. 회사 카탈로그는 원본 CSV 없이 생성된 JSON과 공개 조사 자료로 빌드됩니다.

## 강사 운영 · 4시간

| `OPEN_STAGE` | 누적 오픈 범위 | 교육 시간 |
| --- | --- | --- |
| 0 | 사업·상품 설정, 모든 미디어 설계 · 월 실행 대기 | 시작 전 |
| 1 | 콘텐츠 강의 주제 · 모든 미디어 실행 | 첫 60분 |
| 2 | 인플루언서 강의 주제 추가 · 모든 미디어 실행 | 다음 60분 |
| 3 | 퍼포먼스 강의 주제 추가 · 모든 미디어 실행 | 다음 60분 |
| 4 | 전체 강의 주제와 회고 · 모든 미디어 실행 | 마지막 60분 |

`.env.local`의 값을 수정하고 참가자에게 새로고침을 안내하세요. 서버가 파일을 매 요청마다 다시 읽으므로 **파일 수정에는 서버 재시작이 필요 없습니다.** 호스팅 서비스의 환경 변수는 파일보다 우선합니다. 배포 대시보드의 환경 변수를 바꾸는 경우 서비스에 따라 재시작·재배포가 필요하며, 서버에 반영된 뒤 참가자가 새로고침해야 합니다.

강의 주제와 시뮬레이션 시간은 별개입니다. 헤더의 교육 주제 메뉴는 강의·회고 맥락을 기록하며, **콘텐츠 → 인플루언서 → 퍼포먼스 순서로 집행하거나 주제당 3개월씩 플레이하는 구조가 아닙니다.** 첫 달부터 콘텐츠·시딩·SA·DA를 자유롭게 조합할 수 있습니다. `OPEN_STAGE`는 선택 가능한 교육 주제를 열고, 0일 때만 월 실행을 대기시킵니다. 선택한 주제·강사가 연 주제와 미디어 이용 범위는 관계없습니다.

**한 번 실행 = 모의 1개월**이며 M1, M2…로 연속 진행합니다. 강의 주제를 바꿔도 월수·미작성 전략·예산·브랜드·소재 나이·구독·SI 작업을 이어받습니다. 단계별 3회와 전체 9개월 제한은 제거했습니다. 회고 주제에서도 추가 실험이 가능합니다. 처음부터 광고를 실행한 경우와 오거닉을 먼저 쌓은 경우를 월별로 비교할 수 있습니다.

기존 v2 기록과 단계별 임시 설계는 보존합니다. 기존에 선택한 주제의 임시 설계를 상품별 공통 월별 설계로 복사하고, 이후에는 주제 전환으로 설계가 바뀌지 않습니다. 10개월 이상 진행한 기록도 같은 브라우저 저장 공간에서 복원됩니다.

강의의 각 60분은 개념·사례·실험·토론을 섞어 운영할 수 있으며, 실제 시간이나 강의 주제별 실행 횟수를 강제하지 않습니다. 마지막 시간에는 매출 전망과 진행 기록을 비교하고 인사이트·실행 계획을 작성합니다.

`WORKSHOP_ID`를 바꾸면 다른 저장 공간을 사용합니다. 같은 교육에서는 유지하세요. `WORKSHOP_NAME`은 백업의 워크숍 정보에 들어갑니다.

## 사업과 상품

비즈니스: 이름, 업종, 판매 대상(B2C/B2B/B2B2C/B2G), 핵심 고객(선택).

상품: 상품/서비스명, 판매 가격, 판매 구조(단일 판매형·시간 투입형·구독형), 핵심 가치(선택). 비즈니스에 여러 상품을 등록하고 선택하여 상품별 미디어 믹스와 성과를 관리합니다. 브랜드 인지도·신뢰는 기업 전체에서 공유하고, 재구매·갱신 고객은 상품별로 구분합니다.

업종은 커머스·뷰티·식품·교육·SaaS·제조·전문 서비스·여행·기타로 구분합니다. 각 업종은 콘텐츠 유입 배수, 광고 CPC, 리드 생성, 재관심, 구매 전환, 가격 기준점이 다릅니다. **모든 값은 교육용 가정이며 실제 산업 평균이 아닙니다.** 자유 입력한 문구를 AI가 분석하지는 않습니다.

모든 선택 UI는 Radix Select를 사용하며 기본 브라우저 드롭다운을 표시하지 않습니다. 모달은 Radix Dialog로 포커스 이동·가두기·Escape 처리를 제공합니다. 앱은 다크 모드가 기본이며 하단 탭으로 화면을 전환합니다.


## CSV 기업 자동완성과 상품군

비즈니스 이름 입력란에서 회사명·브랜드·별칭·사업 설명으로 검색할 수 있습니다. 원본 `applications-2026-11-01.csv`의 확정 신청 47건을 중복 정리하여 기업/아이디어 40개 항목으로 구성했습니다. 도슨티·뷰릿·웰킷의 이름 변형을 통합하고, 회사명이 없는 9개 항목은 아이디어로 구분합니다. 똑똑한개발자는 별도 추가했으며 SI와 pluuug Basic/Team/Agency를 따로 등록할 수 있습니다.

선택하면 기업명·추천 업종·판매 대상·핵심 고객·소개를 채웁니다. 불명확한 판매 대상은 다시 선택해야 합니다. B2G도 지원합니다. 기업 선택만으로 상품을 만들지 않으며, 별도의 상품 생성 화면에서 불러옵니다. 기존에 수동 입력한 회사도 이름이 맞으면 상품 템플릿을 사용할 수 있습니다.

2026-11-05 기준 40개 기업·아이디어 모두에 총 75개 상품군을 연결했습니다. 공개 상품·서비스 소개 33개는 `research/company-products.mjs`에 원문 URL·확인일·가격 조건을 기록합니다. 판매 조건 미확인/베타 소개는 별도로 표시하고, 미확인 가격은 `null`로 두어 사용자 입력을 요구합니다. 실제 판매 가격과 영업 조건은 변동될 수 있습니다. 판매 구조는 수정 가능한 추천이며, 투입 시간과 해지율은 공개 기업 지표로 추정하지 않습니다.

공개 상품을 특정하기 어려운 기업과 사업 아이디어에는 신청 사업 설명·유사 업종의 상품 구성을 바탕으로 초안 42개를 제공합니다. `research/product-drafts.mjs`에서 기업별 초안을 관리하며, 새 CSV 항목에도 업종별 기본 초안을 제공합니다. 상품군 선택 메뉴와 설명에는 **업종 기반 초안**을 표시하고 작성 근거를 안내합니다. 초안은 실제 출시 상품으로 간주하지 않으며 가격·공개 출처 URL은 `null`입니다. 불러오면 상품명·핵심 가치·추천 판매 구조를 채우고 가격은 직접 입력합니다. 등록 후에도 초안 표시와 근거를 보관합니다.

추가 조사 경로와 동명이업 구분은 [조사 메모](research/company-product-notes.md)에 기록했습니다. CSV의 무인화연구소는 여행 기록 앱이므로, 기존에 잘못 연결된 무인공간 운영 업체의 웹사이트·상품을 제외하고 여행 기록 상품군 초안으로 교체했습니다.

주요 출처: [똑똑한개발자 서비스](https://www.toktokhan.dev/), [pluuug 요금제](https://www.pluuug.com/pricing), [도슨티 GEO](https://geo.docenty.ai/), [뷰릿](https://www.beaurit.net/), [반조 손보다](https://banzo.co.kr/), [호스탠다드](https://www.hostandard.kr/). 각 상품의 출처는 등록 화면에서도 열 수 있습니다.

```sh
npm run catalog
```

원본 CSV가 있으면 다시 읽고, 없으면 기존에 생성한 안전한 카탈로그에 조사 내용을 병합합니다. 개발 시작/빌드 전에도 실행됩니다. 웹 가격을 자동 재수집하지는 않습니다. 제품 조사 자료와 확인일은 수동 갱신하세요.

생성 파일은 `src/data/company-catalog.json`이며 회사 관련 필드만 허용합니다. 신청자 이름·이메일·전화·기타 신청 답변은 포함하지 않습니다. 원본 신청 CSV는 Git 제외 대상이며, 개발/프로덕션 서버에서도 해당 CSV 요청을 막습니다. 배포 시 원본 CSV를 넣지 않아도 생성된 카탈로그로 동작합니다.

## 미디어 믹스

- 블로그 체험단: 사용 후기와 구매 신뢰
- 블로그 기자단: 정보 확산과 도달
- 파워블로그: 인지도와 영향력
- 블로그 시딩: 검색 접점과 유입
- 온드블로그: 전문성과 다음 달 검색 자산
- 카페 침투·커뮤니티: 관련 맥락에서의 정보 작성과 공감
- 플랫폼 직접 작성: 브런치·링크드인 등 직접 소통
- 마이크로 인플루언서·전문가·메가 인플루언서
- SA 검색광고·DA 디스플레이·소셜 DA

이번 달 발행·성사 수량과 단가로 외부 집행비를 계산합니다. 온드블로그·카페·플랫폼 직접 작성은 추가 현금 집행비 0원이며 내부 마케터의 업무 시간을 사용합니다. 인원·1인 월 시간·역량은 비즈니스 생성/수정에서 정합니다. 일반 역량 기준 온드블로그 4시간, 카페 1시간, 플랫폼 2시간/편이며 시딩 접촉은 15분/명입니다. 역량은 속도(주니어 0.7/일반 1/숙련 1.4배)와 효과(0.8/1/1.2배)에 반영됩니다. 미배분 예산은 소비하지 않습니다. 수량을 늘릴수록 트래픽과 브랜드 효과에는 체감 효율이 적용됩니다. 실행 시 해당 월만 기록되며, 3·6개월 매출 전망은 월별 전략을 직접 조정하는 별도 미리보기입니다.

## 월별 전략 · 광고비 축소 시뮬레이션

매달 해당 월의 발행량·접촉 수·광고 집행량을 정하고 실행합니다. 매월/최초 발행 선택 UI는 제거했으며, 예전 저장 자료의 `cadence` 필드는 읽기 호환을 위해 보관하지만 계산에 적용하지 않습니다. 월 실행을 완료하면 다음 달 설계의 수량과 가설을 비웁니다. `이전 전략 불러오기`로 해당 상품의 마지막 실행 전략을 복사하고 수정할 수 있습니다. 과거 캠페인 기록은 그대로 보존합니다.

매출 전망의 월별 전략 표에서 각 월의 온드블로그 발행량과 SA·DA·소셜 광고 집행 비율(100/75/50/25/0%)을 정합니다. 다른 미디어의 수량은 현재 전략을 유지합니다. 광고 유지·2개월 유지 후 50%·다음 달 광고 중단 시나리오와 매출 그래프를 비교할 수 있습니다. 광고 수량은 정수 단위로 내림해 집행 비율에 적용하며, 월별 표에 실제 예상 비용과 유입을 표시합니다. 표·그래프·CSV는 동일한 월별 전략으로 계산합니다. 미래 설계는 예측 기간과 함께 브라우저에 저장되지만 실행 이력에는 반영되지 않습니다. 예산·내부 가용 시간(온드·시딩·SA 운영·DA 소재 제작)을 초과하는 월은 표시하며, 실제 실행 전 배정을 조정해야 합니다.

SA·DA·소셜 광고는 해당 월 방문만 만들고 검색 자산·인지도·신뢰를 직접 축적하지 않습니다. 광고 중단 시 광고 유입은 0이 됩니다. 온드 콘텐츠는 검색 자산과 신뢰를 만들고, 검색 자산은 월 4% 감쇠하며 다음 달부터 자연 유입에 기여합니다. 인지도는 온드·페이드 기여분으로 나눠 기본 월 유지율 94%/86%를 적용합니다. 비즈니스 설정에서 온드 유지율을 조정하면 페이드는 8%p 낮게 적용합니다. 기존 인지도는 기여 출처가 없어 페이드 기여분으로 이어받습니다. 모두 교육용 가정이며 실제 시장 수치를 나타내지 않습니다.

AARRR은 가로 깔때기로 표시합니다. 방문 → 리드 → 재관심 → 신규 구매/계약 수요의 코호트 수를 연결하며, 추천 유입은 전체 방문에 합류하는 별도 경로로 표시합니다. 서비스 완료와 구독 갱신은 신규 구매와 구분하여 인식 매출에 표시합니다. 작은 하위 코호트도 읽을 수 있도록 띠 두께는 제곱근 비례이며 정확한 수치를 함께 표시합니다.

## 실행한 과거 월 수정

미디어 믹스 위의 `설계할 월 선택`에서 1개월 차부터 모든 실행 월을 선택합니다. 진행 기록에서도 `이 달 전략 수정`으로 진입할 수 있습니다. 과거 달을 편집할 때는 당시 기업·상품·가격·인력과 해당 월 시작 전 누적 상태를 사용하며, 최신 계산 모형으로 미리 계산합니다. 현재의 다음 달 설계는 별도 보존합니다. 구버전의 최초 발행 목표는 해당 월에 실제 실행했던 수량으로 해석해 중복 발행하지 않습니다. 수정안은 새로고침 후에도 이어집니다.

여러 달의 미디어 수량·예산·소재 운영을 바꿀 수 있습니다. 가장 먼저 바꾼 달 이전의 저장 결과는 그대로 두고, 그달부터 마지막 실행 월까지 이후 전략을 유지하면서 고객·구독·SI 대기·브랜드·검색 자산·소재 나이를 연속 재계산합니다. 변경 전후 기업 누적 매출·집행비·ROAS와 월별 결과를 비교한 뒤 `수정안 전체 적용`으로 반영합니다. 재계산 때문에 이후 달의 비용·작업량이 한도를 넘으면 해당 월을 안내하고 적용하지 않습니다.

클라이언트의 미리보기와 `/api/replay`는 `timeline.mjs`의 동일한 순차 계산을 사용합니다. 서버에는 원본 신청 데이터나 전체 결과 대신 필요한 과거 설정·월별 계획·시작 상태를 보내고, 모든 월이 유효한 경우에만 완성된 결과를 돌려줍니다. 실패·취소·연결 오류에는 원래 이력을 유지합니다. 서버리스 재계산 입력 한도는 2MB이며 서버에 기록을 저장하지 않습니다.

적용 직전 이력 한 개를 브라우저에 보관하여 `적용 전 결과로 되돌리기`가 가능합니다. 새 월을 실행하면 그 이전 재계산의 되돌리기는 종료됩니다. 아직 적용하지 않은 수정안이 있으면 먼저 적용하거나 취소한 뒤 새 월을 진행합니다. JSON 백업에는 수정안과 되돌리기 이력도 포함됩니다.

## 업종별 CPC · SA/DA 소재 운영

`research/ad-benchmarks.mjs`에 2026-11-05 확인한 공개 CPC와 출처·업종 대응을 기록합니다. SA는 [WordStream/LocaliQ 2026 검색광고](https://www.wordstream.com/blog/2026-google-ads-benchmarks), 소셜 DA는 [2026 Meta 트래픽 목적 캠페인](https://www.wordstream.com/blog/facebook-ads-benchmarks-2026)의 해외 표본 CPC를 참고합니다. 원문 USD와 교육용 고정 환산 1달러=1,400원을 화면에 같이 표시합니다. 실시간 환율이나 국내 네이버·카카오 실측 평균이 아닙니다. SaaS·전문 서비스는 기업 서비스 인접 업종을 사용하며 매핑을 공개합니다. 일반 디스플레이 DA는 SA 참고 CPC × 18%라는 별도 게임용 추정으로 표시하며 실측값으로 표현하지 않습니다.

SA는 구매 의도/탐색 키워드를 선택합니다. 탐색은 CPC × 0.7과 낮은 구매 의도로 더 많은 방문과 낮은 전환의 균형을 실험합니다. 집행 월마다 일반 역량 기준 문안·키워드 운영 2시간을 사용하고 DA 소재 피로도는 적용하지 않습니다. CPC를 두 번 보정하지 않도록 광고 클릭은 `집행비 / 전략·소재 반영 CPC`로 계산합니다. 다른 미디어의 유입 체감 계수는 광고 CPC에 중복 적용하지 않습니다.

DA와 소셜 DA는 채널별 이미지/숏폼 형식과 1/2/3개월 교체 또는 무교체를 선택합니다. 최초 집행·형식 변경에는 새 소재가 필수이며, 이미지 6시간·영상 16시간/세트를 내부 마케터에게 배정합니다. 마케터 역량은 제작 속도와 새 소재 품질에 반영하고, 제작된 소재의 품질은 이후 인력이 바뀌어도 소급 변경하지 않습니다. 3개월 교체는 첫 달 제작 후 세 달 사용하고 네 번째 달에 다시 제작하는 뜻입니다. 이번 달만 강제 교체하거나 미래 월별 표에서 신규 제작/기존 유지로 덮어쓸 수 있습니다. 강제 교체 명령은 다음 달에 자동 반복하지 않습니다.

동일 소재의 첫째~여섯째 달 기본 클릭 효율은 1/0.92/0.78/0.65/0.55/0.45, 전환 효율은 1/0.88/0.65/0.48/0.35/0.25로 둡니다. 이후 하한을 유지합니다. 세 번째 달에는 CPC가 높아져 같은 집행비로 구매하는 클릭이 줄고 DA의 전환 기여도도 줄어듭니다. 신규 제작하면 이 효과를 회복하지만 온드·시딩 업무와 동일한 내부 가용 시간을 사용합니다. 영상은 클릭 ×1.1·전환 ×1.08의 가정을 추가합니다. 피로도는 DA 방문에만 적용하며 SA·오거닉 방문을 함께 벌점 처리하지 않습니다.

[Google 캠페인 유형](https://support.google.com/google-ads/answer/2567043?hl=ko)과 [Amazon Ads의 소재 피로도 설명](https://advertising.amazon.com/en-ca/library/guides/ad-fatigue)은 유형·소재 관리 원리의 참고 자료입니다. 위 감쇠율·제작 시간·키워드/영상 보정은 공개 자료에서 실측한 수치가 아닌 교육용 설계입니다. 소재 상태는 상품·채널별로 브라우저에 저장하고, 광고를 멈춘 달에도 제작물의 달력상 나이는 증가합니다. 월별 표·매출 그래프·CSV는 같은 소재 상태와 제작 계획을 사용합니다.

## 인플루언서 시딩

인플루언서 시딩은 접촉 인원과 예상 발행 건수를 구분합니다. 협찬 8%, 유료 30%, 레퍼럴 5%의 재현 가능한 기대값을 사용하며, 협찬 접촉 10명은 0.8건 예상 발행입니다. 이는 교육용 가정이며 실제 발행 성공을 보장하지 않습니다. 제품/서비스의 협찬 가능 여부와 성사 건당 제공·배송 원가는 상품에서 설정합니다. 미설정 원가는 판매가의 30%로 가정합니다. 협찬 불가 상품은 유료 또는 레퍼럴 제안으로 바꿔야 합니다.

유료 사례비는 성사 건당 적용하며 레퍼럴 수수료는 추천 유입의 신규 매출에만 적용합니다(갱신 제외). 서비스는 이월 작업과 함께 수수료율도 이어받아 완료 월에 비용을 계산합니다. 협찬 원가·사례비·레퍼럴 수수료는 집행비와 예산 검증에 포함합니다. 시딩 성사율·수수료는 외부 플랫폼 연동 없이 모형으로 계산합니다.

강의에서 제시한 메가 인플루언서 범위: 숏폼 500/650/800만원, 롱폼 3,000/4,000/5,000만원 중 선택합니다. 서버에서도 범위를 검증하며 실제 견적의 보장은 아닙니다.

## AARRR 계산과 ROAS

`model.mjs`가 브라우저 미리보기와 서버 실행의 공통 계산입니다.

1. **Acquisition**: 미디어 유입 + 오거닉 유입 + 기존 고객의 추천 방문.
2. **Activation**: 전체 방문 × 업종 리드 생성률 × 가격 계수 × 이전 브랜드 신뢰.
3. **Retention**: 관심 리드 중 추가 관심·후속 접촉에 도달하는 수. 업종 재관심률과 이전 신뢰를 반영합니다. 장기 구독 유지율과는 별개의 지표입니다.
4. **Referral**: 이전까지의 누적 고객 × 업종 추천 계수 × 추천 의향. 다음 달 Acquisition에 추가되며 구매의 필수 전 단계가 아닙니다.
5. **Revenue**: 재관심 리드 × 업종 구매율 × 가격 계수 × 신뢰 × 미디어 구매 의도로 구매/계약 수요를 구하고, 판매 구조에 따라 판매·서비스 완료·구독 갱신 매출을 계산합니다.

업종별 가격 기준점 대비 상품 가격비를 `r`이라고 하면:

- 리드 가격 계수 = `1 / (1 + r^0.65)`
- 구매 가격 계수 = `1 / (1 + r^0.85)`

같은 업종·미디어·브랜드에서는 가격이 높아질수록 두 비율이 모두 낮아집니다. 인구 수는 내림 처리하므로 작은 예산/높은 가격에서는 전환이 0일 수 있습니다.

- **마케팅 ROAS** = 해당 기간 미디어 유입에 귀속한 매출 ÷ 추가 집행비(외부 발행비·협찬 원가·레퍼럴 수수료) × 100. 추가 집행비가 0원이면 —로 표시합니다.
- **퍼포먼스 ROAS** = SA·DA·소셜 광고에 귀속한 매출 ÷ 해당 광고비 × 100.
- **MER** = 오거닉·추천·재구매를 포함한 전체 매출 ÷ 추가 집행비(외부 발행비·협찬 원가·레퍼럴 수수료) × 100. 추가 집행비가 0원이면 —로 표시합니다.

구매 시점의 매출 귀속은 방문 출처 비중을 쓰는 단순 모형입니다. 시간 투입형의 이월 작업은 원래 유입 비중을 가중 평균으로 보관해 완료 시점에 반영합니다. 실제 어트리뷰션은 아닙니다. 광고비/구매가 0인 비율은 `—`로 표시하며 무한대나 가짜 최소 1건을 생성하지 않습니다.

단일 판매형은 판매 수량 × 상품 가격이며 자동 재구매를 가정하지 않습니다. 이전 버전의 반복 구매 상품은 기존 월 8% 재구매 규칙을 보존합니다.

시간 투입형(SI·용역·대행)은 **건당 투입 시간**과 **이 상품에 배정한 월 시간**을 설정합니다. 가용 시간 안에서 작업하며, 초과 수요·부분 진행 시간은 상품별로 다음 달에 이월합니다. 한 건이 여러 달 걸릴 수도 있습니다. **완료한 건 × 계약 단가**만 매출에 넣고 미완료 수요 환산액은 제외합니다. 이는 교육용 완료 시점 전액 인식 가정이며 실제 수익 인식 정책은 아닙니다. 여러 서비스 상품의 배정 시간 합계가 실제 팀 용량을 넘지 않도록 사용자가 설정해야 합니다. 전사 시간 배분 최적화는 구현하지 않습니다.

구독형은 **월 구독료**와 **모의 월 해지율**을 설정합니다. 기존 활성 구독자 × (1 − 해지율)을 정수 내림하여 갱신 수를 계산하고 신규 가입자를 더합니다. `MRR = 활성 구독자 × 월 구독료`, `ARR = 현재 MRR × 12`입니다. ARR은 실제 12개월 매출 예측이 아닌 연환산 지표입니다. 새 상품의 초기 해지율은 5%인 교육용 가정이며 기업의 실제 수치가 아닙니다. 해지율을 저장하지 않았던 기존 구독은 이전 35% 해지/65% 갱신 가정을 유지합니다.

한 상품을 마케팅하는 달에도 다른 상품의 구독 갱신·해지·기존 서비스 작업은 진행됩니다. 신규 유입은 선택한 캠페인 상품에만 배분합니다. 기업 매출 합계는 선택 상품과 다른 상품의 갱신·완료 매출을 합산하며, 선택 상품 매출은 별도로 표시합니다. 시간 투입형은 대기 작업의 마케팅/자연 유입 비중을 가중 평균으로 보관해 완료 월에 귀속합니다. 계약별 원가·단가 변동·세부 검수·마일스톤별 수익 인식은 구현하지 않습니다.

## 브랜드와 오거닉

인지도·신뢰·추천 의향이 각각 0–100으로 누적됩니다. 미디어별로 역할이 다르며, 고객이 브랜드를 낯설어하는지, 검색하기 시작하는지, 신뢰하는지를 정성적인 문장으로 보여줍니다.

이전 월 인지도가 **30점 이상**이면 다음 달의 브랜드 검색/오거닉 방문에 영향을 줍니다. 온드블로그는 이전까지 발행한 콘텐츠 자산으로 다음 달부터 별도의 오거닉을 만듭니다. 따라서 첫 달 투자가 즉시 오거닉으로 중복 계산되지 않습니다. 인지도는 온드·페이드 기여분에 각각의 월 유지율을 적용하고, 신뢰·추천 의향은 매월 2% 감소합니다.

오거닉 방문 = `(온드 자산 × 85 + 인지도 임계 효과) × 업종 콘텐츠 배수`.

방문은 중복 제거를 가정한 모형상의 수치입니다. 시장 규모·빈도·계절성·경쟁·원가·마진·실제 타기팅·고객 중복은 정밀하게 구현하지 않습니다. 순이익이나 검증된 매출 예측이 아닙니다.

## 저장과 마이그레이션

기록은 `localStorage`의 `marketing-quest:v2:<WORKSHOP_ID>`에 저장됩니다. 새로고침과 브라우저 재실행 후 복원됩니다. 다른 기기와 동기화하지 않으며, 브라우저 데이터를 지우거나 시크릿 창을 닫으면 사라질 수 있습니다. 한 개 탭에서 플레이하세요.

이전 버전(v1)이 있으면 사업과 상품을 분리하여 복원하고 노트·회고를 유지합니다. 이전 실험은 새 모델과 계산 기준이 달라 AARRR 누적에 넣지 않고 `legacyArchive`로 보관합니다. **v1 원본 키는 삭제하지 않습니다.** 전체 JSON 내보내기에 이전 기록도 포함합니다.

진행 기록 모달에서 JSON 백업, 매출 전망에서 CSV, 최종 회고에서 인쇄/PDF를 제공합니다. 가져오기 기능은 아직 없습니다. 서버는 계산에 필요한 사업·상품·누적 상태를 받지만 DB/파일로 저장하지 않습니다. 공유 PC에서는 참가자별 브라우저 프로필을 구분하세요. 클라이언트 저장값은 변경 가능하므로 성적·시상용 보안 시스템은 아닙니다.

- `src/Dashboard.tsx`, `src/Mix.tsx`, `src/Projection.tsx`: 지표·미디어·상세 예측
- `src/Forms.tsx`, `src/components.tsx`: 독립 엔터티 생성과 Radix UI
- `src/storage.ts`: 브라우저 기록 복원, v1→v2 마이그레이션
- `tests/`: 가격 민감도, 미디어 차이, 업종 효과, 예산, 단계 잠금, 지연 오거닉, ROAS/MER, 저장 복원 검증

UI는 [band5051.com](https://band5051.com/)의 픽셀 풍경·게임 HUD 느낌을 참고한 자체 픽셀 마을로 구성했습니다. 사이트 로고 없이 세 건물에서 비즈니스·미디어 믹스·매출 전망으로 이동합니다. 지도·아이콘·화분은 자체 SVG이며, Galmuri11 한글 픽셀 글꼴을 로컬 번들에 포함해 외부 폰트 연결 없이 표시합니다(SIL OFL 1.1). 각진 패널·버튼·커스텀 선택창과 태블릿 중심의 반응형 화면을 사용합니다.
