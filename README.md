# Marketing Quest

마케팅 교육을 위한 태블릿 중심 다크 UI 시뮬레이션입니다. 비즈니스와 상품을 별도로 생성하고, 미디어 믹스 → AARRR → 매출과 브랜드 변화의 관계를 실험합니다. React + TypeScript + Vite + Express를 사용합니다. DB, 외부 AI API 키는 필요하지 않습니다.

## 실행

```sh
npm install
cp .env.example .env.local
npm run dev
```

기본 포트는 3000입니다. 현재 작업 환경의 `.env.local`은 `PORT=3100`, 테스트용 `OPEN_STAGE=4`를 사용합니다. 사용 중인 포트는 `PORT=3104 npm run dev`처럼 변경할 수 있습니다. 브라우저 기록은 주소와 포트별로 분리됩니다.

```sh
npm test
npm run build
npm start
```

Node.js 22 이상을 사용하세요. 배포는 `npm ci && npm run build` 후 `npm start`로 실행하는 Node.js 호스팅 또는 아래 Vercel 구성을 사용합니다. 정적 파일만 배포하면 설정/실행 API가 동작하지 않습니다.

## Vercel 배포

`vercel.json`은 Vite 프런트엔드와 `api/session.mjs`, `api/simulate.mjs`, `api/replay.mjs` Node 함수를 함께 배포합니다. 로컬 Express와 서버리스 함수는 `simulation.mjs`·`model.mjs`의 같은 검증·계산을 사용하며 DB나 서버 저장소는 사용하지 않습니다. 브라우저 화면 경로는 `/` 하나이며 메뉴 상태는 브라우저 저장소에 보관합니다.

Vercel 프로젝트에 `OPEN_STAGE=4`, `WORKSHOP_ID=marketing-2026`, `WORKSHOP_NAME=마케팅 전략 실전 워크숍`을 설정하면 테스트용으로 전체 단계가 열립니다. 운영 시 `OPEN_STAGE`를 바꾸고 재배포한 뒤 참가자가 새로고침합니다. 원본 신청 CSV, `.env*`, 로컬 결과·스크린샷은 `.vercelignore`로 업로드하지 않습니다. 회사 카탈로그는 원본 CSV 없이 생성된 JSON과 공개 조사 자료로 빌드됩니다.

## 강사 운영 · 4시간

| `OPEN_STAGE` | 누적 오픈 범위 | 교육 시간 |
| --- | --- | --- |
| 0 | 사업·상품 설정, 모든 미디어 설계 · 월 실행 대기 | 시작 전 |
| 1 | 콘텐츠 강의 주제 · 모든 미디어 실행 | 첫 60분 |
| 2 | 인플루언서 강의 주제 추가 · 모든 미디어 실행 | 다음 60분 |
| 3 | 퍼포먼스 강의 주제 추가 · 모든 미디어 실행 | 다음 60분 |
| 4 | 전체 강의 주제와 회고 · 모든 미디어 실행 | 마지막 60분 |

`.env.local`의 값을 수정하고 참가자에게 새로고침을 안내하세요. 서버가 파일을 매 요청마다 다시 읽으므로 **파일 수정에는 서버 재시작이 필요 없습니다.** 호스팅 서비스의 환경 변수는 파일보다 우선합니다. 배포 대시보드의 환경 변수를 바꾸는 경우 서비스에 따라 재시작·재배포가 필요하며, 서버에 반영된 뒤 참가자가 새로고침해야 합니다.

강의 주제와 시뮬레이션 시간은 별개입니다. 헤더의 교육 주제 메뉴는 강의·회고 맥락을 기록하며, **콘텐츠 → 인플루언서 → 퍼포먼스 순서로 집행하거나 주제당 3개월씩 플레이하는 구조가 아닙니다.** 첫 달부터 콘텐츠·시딩·SA·DA를 자유롭게 조합할 수 있습니다. `OPEN_STAGE`는 선택 가능한 교육 주제를 열고, 0일 때만 월 실행을 대기시킵니다. 선택한 주제·강사가 연 주제와 미디어 이용 범위는 관계없습니다.

**한 번 실행 = 모의 1개월**이며 M1, M2…로 연속 진행합니다. 강의 주제를 바꿔도 월수·미작성 전략·예산·브랜드·소재 나이·구독·SI 작업을 이어받습니다. 단계별 3회와 전체 9개월 제한은 제거했습니다. 회고 주제에서도 추가 실험이 가능합니다. 처음부터 광고를 실행한 경우와 오거닉을 먼저 쌓은 경우를 월별로 비교할 수 있습니다.

기존 v2 기록과 단계별 임시 설계는 보존합니다. 기존에 선택한 주제의 임시 설계를 상품별 공통 월별 설계로 복사하고, 이후에는 주제 전환으로 설계가 바뀌지 않습니다. 10개월 이상 진행한 기록도 같은 브라우저 저장 공간에서 복원됩니다.

강의의 각 60분은 개념·사례·실험·토론을 섞어 운영할 수 있으며, 실제 시간이나 강의 주제별 실행 횟수를 강제하지 않습니다. 마지막 시간에는 매출 전망과 진행 기록을 비교하고 인사이트·실행 계획을 작성합니다.

`WORKSHOP_ID`를 바꾸면 다른 저장 공간을 사용합니다. 같은 교육에서는 유지하세요. `WORKSHOP_NAME`은 백업의 워크숍 정보에 들어갑니다.

## 사업과 상품

비즈니스: 이름, 업종, 판매 대상(B2C/B2B/B2B2C/B2G), 핵심 고객(선택).

상품: 상품/서비스명, 판매 가격, 판매 구조(단일 판매형·시간 투입형·구독형), 핵심 가치(선택). 비즈니스에 여러 상품을 등록하고 선택하여 상품별 미디어 믹스와 성과를 관리합니다. 브랜드 인지도·신뢰는 기업 전체에서 공유하고, 재구매·갱신 고객은 상품별로 구분합니다.

업종은 커머스·뷰티·식품·교육·SaaS·제조·전문 서비스·여행·기타로 구분합니다. 각 업종은 콘텐츠 유입 배수, 광고 CPC, 리드 생성, 재관심, 구매 전환, 가격 기준점이 다릅니다. **모든 값은 교육용 가정이며 실제 산업 평균이 아닙니다.** 자유 입력한 문구를 AI가 분석하지는 않습니다.

모든 선택 UI는 Radix Select를 사용하며 기본 브라우저 드롭다운을 표시하지 않습니다. 모달은 Radix Dialog로 포커스 이동·가두기·Escape 처리를 제공합니다. 앱은 다크 모드가 기본이며 하단 탭으로 화면을 전환합니다.


## CSV 기업 자동완성과 상품군

비즈니스 이름 입력란에서 회사명·브랜드·별칭·사업 설명으로 검색할 수 있습니다. 원본 `applications-2026-11-01.csv`의 확정 신청 47건을 중복 정리하여 기업/아이디어 40개 항목으로 구성했습니다. 도슨티·뷰릿·웰킷의 이름 변형을 통합하고, 회사명이 없는 9개 항목은 아이디어로 구분합니다. 똑똑한개발자는 별도 추가했으며 SI와 pluuug Basic/Team/Agency를 따로 등록할 수 있습니다.

선택하면 기업명·추천 업종·판매 대상·핵심 고객·소개를 채웁니다. 불명확한 판매 대상은 다시 선택해야 합니다. B2G도 지원합니다. 비즈니스를 선택하고 저장하면 해당 기업의 상품 목록도 함께 준비합니다. 기업을 찾을 수 없으면 선택한 업종에 맞는 상품 초안 2개를 만듭니다. 상품은 나의 상품에서 개별 수정·삭제·추가할 수 있습니다. 기존에 수동 입력한 회사도 이름이 맞으면 상품 템플릿을 사용할 수 있습니다.

2026-11-05 기준 40개 기업·아이디어 모두에 총 75개 상품군을 연결했습니다. 공개 상품·서비스 소개 33개는 `research/company-products.mjs`에 원문 URL·확인일·가격 조건을 기록합니다. 판매 조건 미확인/베타 소개는 별도로 표시하고, 카탈로그의 미확인 가격은 `null`로 보관합니다. 비즈니스 저장으로 자동 준비하는 상품에는 별도의 교육용 예시 가격을 넣고 `priceEstimated`로 표시하며 실제 판매가로 수정하도록 안내합니다. 실제 판매 가격과 영업 조건은 변동될 수 있습니다. 판매 구조는 수정 가능한 추천이며, 투입 시간과 해지율은 공개 기업 지표로 추정하지 않습니다.

공개 상품을 특정하기 어려운 기업과 사업 아이디어에는 신청 사업 설명·유사 업종의 상품 구성을 바탕으로 초안 42개를 제공합니다. `research/product-drafts.mjs`에서 기업별 초안을 관리하며, 새 CSV 항목에도 업종별 기본 초안을 제공합니다. 상품군 선택 메뉴와 설명에는 **업종 기반 초안**을 표시하고 작성 근거를 안내합니다. 초안은 실제 출시 상품으로 간주하지 않으며 가격·공개 출처 URL은 `null`입니다. 불러오면 상품명·핵심 가치·추천 판매 구조를 채우고 가격은 직접 입력합니다. 등록 후에도 초안 표시와 근거를 보관합니다.

추가 조사 경로와 동명이업 구분은 [조사 메모](research/company-product-notes.md)에 기록했습니다. CSV의 무인화연구소는 여행 기록 앱이므로, 기존에 잘못 연결된 무인공간 운영 업체의 웹사이트·상품을 제외하고 여행 기록 상품군 초안으로 교체했습니다.

주요 출처: [똑똑한개발자 서비스](https://www.toktokhan.dev/), [pluuug 요금제](https://www.pluuug.com/pricing), [도슨티 GEO](https://geo.docenty.ai/), [뷰릿](https://www.beaurit.net/), [반조 손보다](https://banzo.co.kr/), [호스탠다드](https://www.hostandard.kr/). 각 상품의 출처는 등록 화면에서도 열 수 있습니다.

```sh
npm run catalog
```

원본 CSV가 있으면 다시 읽고, 없으면 기존에 생성한 안전한 카탈로그에 조사 내용을 병합합니다. 개발 시작/빌드 전에도 실행됩니다. 웹 가격을 자동 재수집하지는 않습니다. 제품 조사 자료와 확인일은 수동 갱신하세요.

생성 파일은 `src/data/company-catalog.json`이며 회사 관련 필드만 허용합니다. 신청자 이름·이메일·전화·기타 신청 답변은 포함하지 않습니다. 원본 신청 CSV는 Git 제외 대상이며, 개발/프로덕션 서버에서도 해당 CSV 요청을 막습니다. 배포 시 원본 CSV를 넣지 않아도 생성된 카탈로그로 동작합니다.

## 미디어 믹스

- 블로그 체험단: 사용 후기와 구매 신뢰
- 블로그 기자단: 정보 확산과 도달
- 파워블로그: 인지도와 영향력
- 블로그 시딩: 검색 접점과 유입
- 온드블로그: 전문성과 다음 달 검색 자산
- 카페 침투·커뮤니티: 관련 맥락에서의 정보 작성과 공감
- 플랫폼 직접 작성: 브런치·링크드인 등 직접 소통
- 마이크로 인플루언서·전문가·메가 인플루언서
- SA 검색광고·DA 디스플레이·소셜 DA

이번 달 발행·성사 수량과 단가로 외부 집행비를 계산합니다. 온드블로그·카페·플랫폼 직접 작성은 추가 현금 집행비 0원이며 내부 마케터의 업무 시간을 사용합니다. 인원·1인 월 시간·역량은 비즈니스 생성/수정에서 정합니다. 일반 역량 기준 온드블로그 4시간, 카페 1시간, 플랫폼 2시간/편이며 시딩 접촉은 15분/명입니다. 역량은 속도(주니어 0.7/일반 1/숙련 1.4배)와 효과(0.8/1/1.2배)에 반영됩니다. 미배분 예산은 소비하지 않습니다. 수량을 늘릴수록 트래픽과 브랜드 효과에는 체감 효율이 적용됩니다. 실행 시 해당 월만 기록되며, 매출 전망은 M1~M12의 저장한 계획과 실행 결과를 한 표에서 확인합니다.

## M1~M12 연간 미디어 믹스 계획

입력과 실행 범위는 **M1부터 M12까지**로 고정합니다. 미디어 믹스의 월 선택에서 아직 실행하지 않은 달도 열어 상품·모든 매체 수량·소재·시딩 조건·가설을 미리 저장할 수 있습니다. 월별 내용은 기업별 `monthlyPlans`에 보관하며, 새로고침 후 선택한 달과 작성 내용이 복원됩니다. 교육 주제와 관계없이 매체를 조합하고, 실제 실행은 M1부터 차례로 진행합니다. 12개월 실행 이후에는 기존 달의 전략 수정·재계산을 사용할 수 있으며 M13 입력·실행은 허용하지 않습니다. 이전에 존재하던 12개월 초과 기록은 삭제하지 않습니다.

**이후 빈 달에 복사**는 현재 조합을 M12까지 미작성 달에만 복사합니다. 유료 미디어는 각 달의 재투자 예산에 맞춰 배분 비중을 유지하며 정수 내림합니다. 온드·접촉 업무는 같은 수량을 유지합니다. 이미 작성하거나 초기화한 달은 덮어쓰지 않습니다. 각 달은 복사 후에도 개별 수정할 수 있습니다. 앞선 계획의 매출이 달라지면 이후 예상 예산도 이어 바뀌고, 예산·내부 시간을 넘는 달은 경고합니다.

**초기화**는 선택한 달의 모든 미디어 배정 수량을 0으로 바꿉니다. 예산 정책·실행 기록·가설·단가 설정은 보존하고, 현재 화면에서 **초기화 취소**로 방금 지운 수량을 되돌릴 수 있습니다. 실행한 달에서는 적용 전 수정안으로만 취급합니다.

매출 전망은 3/6개월 선택 대신 12개월 고정 표로 제공하며 상품·실행/계획 상태·사용 가능 예산·전월 매출 재투자·집행비·기업 매출을 표시합니다. ‘설계/수정’으로 해당 월 미디어 믹스를 엽니다. 실행한 달은 실제 저장 결과, 미래 달은 그 이전의 실행·계획을 차례로 이어 계산한 예상입니다. 미작성 달은 새 집행 0으로 계산하되 기존 구독 갱신·작업 완료·오거닉은 이어집니다. AARRR 상세와 CSV도 같은 M1~M12 데이터를 사용합니다.

## 실행한 과거 월 수정

미디어 믹스 위의 `설계할 월 선택`에서 1개월 차부터 모든 실행 월을 선택합니다. 진행 기록에서도 `이 달 전략 수정`으로 진입할 수 있습니다. 과거 달을 편집할 때는 당시 기업·상품·가격·인력과 해당 월 시작 전 누적 상태를 사용하며, 최신 계산 모형으로 미리 계산합니다. 현재의 다음 달 설계는 별도 보존합니다. 구버전의 최초 발행 목표는 해당 월에 실제 실행했던 수량으로 해석해 중복 발행하지 않습니다. 수정안은 새로고침 후에도 이어집니다.

여러 달의 미디어 수량·예산·소재 운영을 바꿀 수 있습니다. 가장 먼저 바꾼 달 이전의 저장 결과는 그대로 두고, 그달부터 마지막 실행 월까지 이후 전략을 유지하면서 고객·구독·SI 대기·브랜드·검색 자산·소재 나이를 연속 재계산합니다. 변경 전후 기업 누적 매출·집행비·ROAS와 월별 결과를 비교한 뒤 `수정안 전체 적용`으로 반영합니다. 재계산 때문에 이후 달의 비용·작업량이 한도를 넘으면 해당 월을 안내하고 적용하지 않습니다.

클라이언트의 미리보기와 `/api/replay`는 `timeline.mjs`의 동일한 순차 계산을 사용합니다. 서버에는 원본 신청 데이터나 전체 결과 대신 필요한 과거 설정·월별 계획·시작 상태를 보내고, 모든 월이 유효한 경우에만 완성된 결과를 돌려줍니다. 실패·취소·연결 오류에는 원래 이력을 유지합니다. 서버리스 재계산 입력 한도는 2MB이며 서버에 기록을 저장하지 않습니다.

적용 직전 이력 한 개를 브라우저에 보관하여 `적용 전 결과로 되돌리기`가 가능합니다. 새 월을 실행하면 그 이전 재계산의 되돌리기는 종료됩니다. 아직 적용하지 않은 수정안이 있으면 먼저 적용하거나 취소한 뒤 새 월을 진행합니다. JSON 백업에는 수정안과 되돌리기 이력도 포함됩니다.

## 업종별 CPC · SA/DA 소재 운영

`research/ad-benchmarks.mjs`에 2026-11-05 확인한 공개 CPC와 출처·업종 대응을 기록합니다. SA는 [WordStream/LocaliQ 2026 검색광고](https://www.wordstream.com/blog/2026-google-ads-benchmarks), 소셜 DA는 [2026 Meta 트래픽 목적 캠페인](https://www.wordstream.com/blog/facebook-ads-benchmarks-2026)의 해외 표본 CPC를 참고합니다. 원문 USD와 교육용 고정 환산 1달러=1,400원을 화면에 같이 표시합니다. 실시간 환율이나 국내 네이버·카카오 실측 평균이 아닙니다. SaaS·전문 서비스는 기업 서비스 인접 업종을 사용하며 매핑을 공개합니다. 일반 디스플레이 DA는 SA 참고 CPC × 18%라는 별도 게임용 추정으로 표시하며 실측값으로 표현하지 않습니다.

SA는 구매 의도/탐색 키워드를 선택합니다. 탐색은 CPC × 0.7과 낮은 구매 의도로 더 많은 방문과 낮은 전환의 균형을 실험합니다. 집행 월마다 일반 역량 기준 문안·키워드 운영 2시간을 사용하고 DA 소재 피로도는 적용하지 않습니다. CPC를 두 번 보정하지 않도록 광고 클릭은 `집행비 / 전략·소재 반영 CPC`로 계산합니다. 다른 미디어의 유입 체감 계수는 광고 CPC에 중복 적용하지 않습니다.

DA와 소셜 DA는 채널별 이미지/숏폼 형식과 1/2/3개월 교체 또는 무교체를 선택합니다. 최초 집행·형식 변경에는 새 소재가 필수이며, 이미지 6시간·영상 16시간/세트를 내부 마케터에게 배정합니다. 마케터 역량은 제작 속도와 새 소재 품질에 반영하고, 제작된 소재의 품질은 이후 인력이 바뀌어도 소급 변경하지 않습니다. 3개월 교체는 첫 달 제작 후 세 달 사용하고 네 번째 달에 다시 제작하는 뜻입니다. 이번 달만 강제 교체하거나 미래 월별 표에서 신규 제작/기존 유지로 덮어쓸 수 있습니다. 강제 교체 명령은 다음 달에 자동 반복하지 않습니다.

동일 소재의 첫째~여섯째 달 기본 클릭 효율은 1/0.92/0.78/0.65/0.55/0.45, 전환 효율은 1/0.88/0.65/0.48/0.35/0.25로 둡니다. 이후 하한을 유지합니다. 세 번째 달에는 CPC가 높아져 같은 집행비로 구매하는 클릭이 줄고 DA의 전환 기여도도 줄어듭니다. 신규 제작하면 이 효과를 회복하지만 온드·시딩 업무와 동일한 내부 가용 시간을 사용합니다. 영상은 클릭 ×1.1·전환 ×1.08의 가정을 추가합니다. 피로도는 DA 방문에만 적용하며 SA·오거닉 방문을 함께 벌점 처리하지 않습니다.

[Google 캠페인 유형](https://support.google.com/google-ads/answer/2567043?hl=ko)과 [Amazon Ads의 소재 피로도 설명](https://advertising.amazon.com/en-ca/library/guides/ad-fatigue)은 유형·소재 관리 원리의 참고 자료입니다. 위 감쇠율·제작 시간·키워드/영상 보정은 공개 자료에서 실측한 수치가 아닌 교육용 설계입니다. 소재 상태는 상품·채널별로 브라우저에 저장하고, 광고를 멈춘 달에도 제작물의 달력상 나이는 증가합니다. 월별 표·매출 그래프·CSV는 같은 소재 상태와 제작 계획을 사용합니다.

## 인플루언서 시딩

인플루언서 시딩은 월초 인지도 20·신뢰 25 이상에서만 섭외됩니다. 고관여 상품은 인지도 25·신뢰 35 이상이 필요합니다. 한쪽이라도 미달하면 제안 방식이나 접촉 수와 관계없이 발행·유입·브랜드 효과·협찬비는 0이고 접촉 시간만 소모합니다. 같은 달의 활동으로 조건을 충족해도 다음 달부터 성사됩니다. 유료 마이크로·전문가 등 확정 집행은 이 조건과 별개입니다.

조건 충족 후에는 접촉 인원과 예상 발행 건수를 구분합니다. 제품 협찬 1%, 유료 제안 10%, 레퍼럴 제안 1%의 재현 가능한 기대값을 사용하며, 제품 협찬 접촉 10명은 0.1건 예상 발행입니다. 이는 교육용 가정이며 실제 발행 성공을 보장하지 않습니다. 제품/서비스의 협찬 가능 여부와 성사 건당 제공·배송 원가는 상품에서 설정합니다. 미설정 원가는 판매가의 30%로 가정합니다. 협찬 불가 상품은 유료 또는 레퍼럴 제안으로 바꿔야 합니다.

유료 사례비는 성사 건당 적용하며 레퍼럴 수수료는 추천 유입의 신규 매출에만 적용합니다(갱신 제외). 서비스는 이월 작업과 함께 수수료율도 이어받아 완료 월에 비용을 계산합니다. 협찬 원가·사례비·레퍼럴 수수료는 집행비와 예산 검증에 포함합니다. 시딩 성사율·수수료는 외부 플랫폼 연동 없이 모형으로 계산합니다.

강의에서 제시한 메가 인플루언서 범위: 숏폼 500/650/800만원, 롱폼 3,000/4,000/5,000만원 중 선택합니다. 서버에서도 범위를 검증하며 실제 견적의 보장은 아닙니다.

## AARRR 계산과 ROAS

`model.mjs`가 브라우저 미리보기와 서버 실행의 공통 계산입니다.

1. **Acquisition**: 미디어 유입 + 오거닉 유입 + 기존 고객의 추천 방문.
2. **Activation**: 유입 출처별 방문 × 업종 리드율 × 가격 계수 × 이전 신뢰 × 관여도 × 광고 리드 계수. 출처별 기대 리드를 합산하고 내립니다.
3. **Retention**: 관심 리드 중 추가 관심·후속 접촉에 도달하는 수. 업종 재관심률과 이전 신뢰를 반영합니다. 장기 구독 유지율과는 별개의 지표입니다.
4. **Referral**: 이전까지의 누적 고객 × 업종 추천 계수 × 신뢰·추천 관계 계수. 광고만 운영해 관계 계수가 0이면 추천도 0입니다. 다음 달 Acquisition에 추가되며 구매의 필수 전 단계가 아닙니다.
5. **Revenue**: 재관심 리드 × 업종 구매율 × 가격 계수 × 신뢰 × 미디어 구매 의도로 구매/계약 수요를 구하고, 판매 구조에 따라 판매·서비스 완료·구독 갱신 매출을 계산합니다.

업종별 가격 기준점 대비 상품 가격비를 `r`이라고 하면:

- 리드 가격 계수 = `1 / (1 + r^0.65)`
- 구매 가격 계수 = `1 / (1 + r^0.85)`

같은 업종·미디어·브랜드에서는 가격이 높아질수록 두 비율이 모두 낮아집니다. 인구 수는 내림 처리하므로 작은 예산/높은 가격에서는 전환이 0일 수 있습니다.

- **마케팅 ROAS** = 해당 기간 미디어 유입에 귀속한 매출 ÷ 추가 집행비(외부 발행비·협찬 원가·레퍼럴 수수료) × 100. 추가 집행비가 0원이면 —로 표시합니다.
- **퍼포먼스 ROAS** = SA·DA·소셜 광고에 귀속한 매출 ÷ 해당 광고비 × 100.
- **MER** = 오거닉·추천·재구매를 포함한 전체 매출 ÷ 추가 집행비(외부 발행비·협찬 원가·레퍼럴 수수료) × 100. 추가 집행비가 0원이면 —로 표시합니다.

구매 시점의 매출 귀속은 채널별 `방문 × 리드율 × 구매율`의 전환 기여 비중을 쓰는 단순 모형입니다. SA 인지도 보너스가 DA·콘텐츠 전환까지 올리거나 낮은 전환 채널에 과도하게 매출을 배분하지 않습니다. 시간 투입형의 이월 작업은 원래 유입 비중을 가중 평균으로 보관해 완료 시점에 반영합니다. 실제 어트리뷰션은 아닙니다. 광고비/구매가 0인 비율은 `—`로 표시하며 무한대나 가짜 최소 1건을 생성하지 않습니다.

단일 판매형은 기본적으로 신규 판매만 계산합니다. 상품에서 **재구매 가능**을 선택하면 `기존 해당 상품 고객 × 8% × 신뢰·추천 관계 계수`를 내림해 재구매를 더합니다. 기존 재구매형도 같은 관계 계수를 반영합니다. 일반 상품의 미설정 기본값은 재구매 없음입니다. 서비스는 신규 계약·이월 작업 완료, 구독은 명시한 해지율에 따른 갱신 규칙을 사용합니다.

시간 투입형(SI·용역·대행)은 **건당 투입 시간**과 **이 상품에 배정한 월 시간**을 설정합니다. 가용 시간 안에서 작업하며, 초과 수요·부분 진행 시간은 상품별로 다음 달에 이월합니다. 한 건이 여러 달 걸릴 수도 있습니다. **완료한 건 × 계약 단가**만 매출에 넣고 미완료 수요 환산액은 제외합니다. 이는 교육용 완료 시점 전액 인식 가정이며 실제 수익 인식 정책은 아닙니다. 여러 서비스 상품의 배정 시간 합계가 실제 팀 용량을 넘지 않도록 사용자가 설정해야 합니다. 전사 시간 배분 최적화는 구현하지 않습니다.

구독형은 **월 구독료**와 **모의 월 해지율**을 설정합니다. 기존 활성 구독자 × (1 − 해지율)을 정수 내림하여 갱신 수를 계산하고 신규 가입자를 더합니다. `MRR = 활성 구독자 × 월 구독료`, `ARR = 현재 MRR × 12`입니다. ARR은 실제 12개월 매출 예측이 아닌 연환산 지표입니다. 새 상품의 초기 해지율은 5%인 교육용 가정이며 기업의 실제 수치가 아닙니다. 해지율을 저장하지 않았던 기존 구독은 이전 35% 해지/65% 갱신 가정을 유지합니다.

한 상품을 마케팅하는 달에도 다른 상품의 구독 갱신·해지·기존 서비스 작업은 진행됩니다. 신규 유입은 선택한 캠페인 상품에만 배분합니다. 기업 매출 합계는 선택 상품과 다른 상품의 갱신·완료 매출을 합산하며, 선택 상품 매출은 별도로 표시합니다. 시간 투입형은 대기 작업의 마케팅/자연 유입 비중을 가중 평균으로 보관해 완료 월에 귀속합니다. 계약별 원가·단가 변동·세부 검수·마일스톤별 수익 인식은 구현하지 않습니다.

## 브랜드와 오거닉

인지도·신뢰·추천 의향이 각각 0–100으로 누적됩니다. 미디어별로 역할이 다르며, 고객이 브랜드를 낯설어하는지, 검색하기 시작하는지, 신뢰하는지를 정성적인 문장으로 보여줍니다.

이전 월 인지도 **30점 이상**과 신뢰가 함께 쌓이면 다음 달의 브랜드 검색/오거닉 방문에 영향을 줍니다. DA만으로 인지도가 높아져도 신뢰가 없으면 브랜드 검색이 생기지 않습니다. 온드블로그는 이전까지 발행한 콘텐츠 자산으로 다음 달부터 별도의 오거닉을 만듭니다. 따라서 첫 달 투자가 즉시 오거닉으로 중복 계산되지 않습니다. 인지도는 온드·페이드 기여분에 각각의 월 유지율을 적용하고, 신뢰·추천 의향은 매월 2% 감소합니다.

기본 자산 도달 계수 = `0.003 + min(인지도/50, 1)^2 × min(신뢰/45, 1)`. 온드·유료 블로그 전체 누적 200편 전 이 계수를 0으로 적용합니다. 검색 자산 유입 = `이전 자산 × 65 × 업종 배수 × 기본 계수 × 유입 가능한 자산 비중`이며 미성숙 블로그 자산은 제외합니다. 브랜드 검색은 인지도 30점 임계 효과·신뢰·콘텐츠 기반을 함께 반영합니다. 카페·플랫폼은 외부 접점이므로 초기에도 도달하며, 온드보다 검색 자산 적립은 적습니다.

방문은 중복 제거를 가정한 모형상의 수치입니다. 시장 규모·빈도·계절성·경쟁·원가·마진·실제 타기팅·고객 중복은 정밀하게 구현하지 않습니다. 순이익이나 검증된 매출 예측이 아닙니다.

## 저장과 마이그레이션

기록은 `localStorage`의 `marketing-quest:v2:<WORKSHOP_ID>`에 저장됩니다. 새로고침과 브라우저 재실행 후 복원됩니다. 다른 기기와 동기화하지 않으며, 브라우저 데이터를 지우거나 시크릿 창을 닫으면 사라질 수 있습니다. 한 개 탭에서 플레이하세요.

이전 버전(v1)이 있으면 사업과 상품을 분리하여 복원하고 노트·회고를 유지합니다. 이전 실험은 새 모델과 계산 기준이 달라 AARRR 누적에 넣지 않고 `legacyArchive`로 보관합니다. **v1 원본 키는 삭제하지 않습니다.** 전체 JSON 내보내기에 이전 기록도 포함합니다.

진행 기록 모달에서 JSON 백업, 매출 전망에서 CSV, 최종 회고에서 인쇄/PDF를 제공합니다. 가져오기 기능은 아직 없습니다. 서버는 계산에 필요한 사업·상품·누적 상태를 받지만 DB/파일로 저장하지 않습니다. 공유 PC에서는 참가자별 브라우저 프로필을 구분하세요. 클라이언트 저장값은 변경 가능하므로 성적·시상용 보안 시스템은 아닙니다.

## 브랜드 성장과 전략 편중

`strategy.mjs`의 계수는 요청한 교육 시나리오를 위한 가정이며 CPC 리서치의 실측 전환율이 아닙니다. 업종·가격·관여도·브랜드·소재가 실제 결과를 함께 결정하며 특정 ROAS나 비율을 강제하지 않습니다.

- SA 전환 보너스: `1 + min(인지도/80, 1) × (저관여 1 / 고관여 1.5)`. 클릭 수는 그대로 두고 SA 전환에만 적용합니다.
- 상품 관여도: 저관여/고관여 직접 선택 또는 자동 판단(용역 또는 업종 기준가 3배 이상은 고관여). 고관여는 신뢰 60까지 리드·구매 문턱이 높으며, 전문 콘텐츠·체험 후기·전문가의 신뢰 기여가 중요합니다.
- 광고 편중: 상품별 SA+DA 리소스 비중이 75%를 넘으면 광고 피로가 누적됩니다. 검색 자산·인지·신뢰 기반이 있으면 누적 속도가 느리고, 콘텐츠·인플루언서와 분산하면 회복합니다. 다음 달 전환에 누적 피로를 반영하며 최대 50%까지 효율이 낮아집니다. 소재 교체·작은 수량 변경·상품 전환으로 기존 피로를 초기화하지 않습니다. 소재 피로도는 별도로 적용됩니다.
- 광고 단독 신규 사업은 매월 방문·리드는 발생하지만 블로그 전환 기반이 없어 신규 구매·ROAS는 0입니다. 기존 블로그 기반이 있는 사업도 광고에만 집중하면 콘텐츠 유지 상태와 인지도·신뢰가 감쇠하고 광고 편중이 누적되어 효율이 하락합니다. 특정 ROAS 수치를 강제하지 않습니다.
- 순수 온드블로그 20편/월은 M1~M10 방문·매출 0이며, M11부터 누적 200편의 직접·검색 유입이 열립니다. 인건비·원가·현금 잔고는 계산하지 않으므로 회사 파산을 자동 판정하지 않습니다. 화면의 집행 회수 차액은 매출−집행비이며 순이익이 아닙니다.
- 콘텐츠/인플루언서/광고 중 한 축에 80% 이상을 3개월째 집중하면 재검토 안내와 비광고의 반복 도달 체감을 적용합니다. 달력이나 강의 단계로 전략을 강제하지 않고 1–2개월마다 비교·수정하도록 안내합니다.

추천 믹스는 월초 브랜드 상태에 따라 초기 DA:콘텐츠 **2:8**, 성장 DA:SA:콘텐츠 **2:2:7**(합계 11의 상대 비중), 신뢰·인지 성숙 SA:DA:인플루언서:콘텐츠 **2:1:3:4**로 바뀝니다. 콘텐츠에는 온드뿐 아니라 커뮤니티 직접 작성·체험단 등 외부 접점을 함께 배분합니다. 상품 관여도에 따라 마이크로/전문가를 선택하고 재구매형은 커뮤니티·체험 후기를 우선 배분하며(추천 의향 기여 ×1.2), 예산·실제 소재 형식·마케터 가용 시간 안에서 조정합니다. 비중은 `외부 집행비 + 내부 시간 × 25,000원`이라는 비교용 리소스 단위입니다. 내부 시간 환산값은 실제 집행비·ROAS에 더하지 않습니다. 추천 비율 자체에 성과 보너스를 부여하지 않습니다.

상품 특성과 상품별 광고 편중 이력은 브라우저 저장·월별 예측·과거 월 재계산·API가 같은 모형을 사용합니다. 새 필드가 없는 이전 기록도 읽을 수 있고, 보관 중인 원래 결과는 과거 전략 수정안을 적용하기 전까지 유지합니다.

## 비즈니스 전환과 상품 관리

기업 검색 후 저장하면 `business-state.mjs`가 기업 카탈로그의 상품군을 실제 실험 상품으로 준비합니다. 공개 가격은 그대로 사용하고, 미확인 가격·수행 시간·해지율은 교육용 초기값을 사용합니다. 업종 기반 초안과 예시 가격은 카드 및 수정 화면에서 구분합니다. 같은 기업을 다시 저장해도 직접 수정·삭제한 상품을 덮어쓰지 않습니다. 미등록 기업의 업종을 변경하면 아직 편집하지 않은 자동 생성 초안만 새 업종으로 바꾸고, 직접 편집한 상품은 보존합니다.

다른 기업을 선택하면 상품·월별 전략·실행 기록·메모·회고를 기업별로 보관하며 새 기업은 별도의 초기 상태로 시작합니다. **저장한 비즈니스** 메뉴로 이전 기업을 다시 열 수 있고 새로고침 후에도 유지됩니다. 이전 기업의 고객·구독·브랜드·서비스 대기를 다른 기업의 매출에 합산하지 않습니다. 활성 기업은 루트 상태에, 비활성 기업은 `businessSessions`에 중복 없이 저장합니다.

상품 카드에서 수정·삭제할 수 있습니다. 현재 선택한 상품을 삭제하면 인접 상품을 선택하고, 마지막 상품까지 삭제하면 상품 추가 안내를 표시합니다. 과거 실행 스냅샷과 당시 매출은 남기되 다음 실행의 상품 목록에서는 제외합니다. 삭제 취소는 다음 월을 실행하기 전까지 가능하며 새로고침 후에도 보관합니다. 구독 상품을 삭제하면 향후 갱신 매출에서도 제외됩니다.

## 이전 버전 예산 규칙 · 과거 기록 호환

아래 500만 원·40% 규칙은 과거 기록의 설명입니다. 현재 신규 실행에는 문서 하단의 연간 3,600만 원·월 권장 300만 원 + 전월 매출 30% 규칙을 적용합니다.

새 비즈니스와 기존 비즈니스의 다음 실행에는 **매월 기본 500만 원 + 전월 기업 전체 인식 매출의 40%**를 사용합니다. 첫 달은 전월 매출이 없어 500만 원입니다. 예를 들어 전월 매출 1,000만 원이면 다음 달 예산은 900만 원입니다. 전월 매출을 기준으로 한 달 뒤에 반영하며, 재투자액은 원 단위 내림합니다. 누적 매출이나 아직 발생하지 않은 당월 매출을 먼저 쓰지 않습니다. 미집행 예산은 이월하지 않고 매월 같은 공식으로 새로 계산합니다.

기업 전체 매출에는 다른 상품의 구독 갱신·재구매·완료한 서비스 매출도 포함합니다. 서비스 대기 계약 금액과 ARR은 매출로 간주하지 않습니다. 이전 매출이 줄면 다음 예산도 줄 수 있으며, 당월 실제 집행비가 아닌 사용 가능 한도입니다. 월 전략은 사용자가 직접 배분하고, 추천 믹스는 늘어난 예산 안에서 구성됩니다.

`funding.mjs`가 계산과 기존 데이터 이전을 공유합니다. `Business.budgetPolicy`에 기본액·재투자율, `Memory.lastRevenue`에 바로 이전 달 기업 매출을 보관합니다. 이전 기록에 이 필드가 없으면 마지막 실행의 실제 기업 매출을 사용합니다. 이전에 저장한 고정 예산 기록의 결과·스냅샷은 보존하며 다음 실행부터 새 정책을 적용합니다. 새 정책으로 실행한 과거 달을 수정하면 그 이후 예산도 변경 매출을 이어받아 다시 계산하고, 뒤의 월이 예산을 넘으면 전체 적용을 막고 수정을 안내합니다.

이 절이 앞선 500만 원·40% 재투자 설명을 대체합니다. 새 비즈니스와 기존 비즈니스의 향후 계획은 다음 정책을 적용합니다. 과거 기록의 예산 규칙과 숫자는 보관합니다.

- 연간 시작 자금은 **3,600만 원**이며 M1부터 전액 사용할 수 있습니다. 매월 300만 원을 추가 지급하지 않습니다.
- **월 권장액 = 300만 원 + 전월 기업 전체 매출 × 30%**. 권장액은 목표 배분이며 강제 상한이 아닙니다. 추천 믹스와 자동 복사는 권장액을 참고하되 잔액 안에서 계산합니다.
- **집행 상한 = 연간 시작 자금 + 전월까지 누적 기업 매출 − 전월까지 누적 마케팅 집행비**. 미사용 자금은 계속 남습니다. 당월 매출을 신규 집행비로 미리 당겨 쓰지는 않습니다.
- **다음 달 집행 상한 = 이번 달 시작 잔액 + 이번 달 기업 매출 − 이번 달 집행비**. 매출은 모든 상품의 신규 판매·구독 갱신·이월 작업 완료를 합산합니다. 발행비·협찬 원가·레퍼럴·공구 수수료는 모두 집행비에 포함합니다. 같은 매출의 30%를 실제 잔액에 한 번 더 가산하지 않습니다.
- 잔액 0원에서는 무료 온드 작업·시딩 접촉을 포함한 신규 마케팅을 금지합니다. **신규 집행 없이 한 달 패스**로 진행하며, 기존 자산의 자연 유입·추천, 구독 갱신, 이미 계약한 서비스 완료 매출은 계산합니다. 매출 유입이 없으면 잔액 0원이 유지됩니다.
- 패스 중 기존 매출에 딸린 이월 레퍼럴·공구 수수료는 해당 매출에서 자동 정산하여 잔액 0원이 매출 인식 자체를 막지 않도록 합니다. 수수료를 누적 집행에 기록하고 차감 후 잔액만 다음 달에 사용할 수 있습니다.

누적 매출·집행은 기업별 실행 기록에서 복원하고, 과거 달 수정 시 이후 잔액·권장액도 이어 계산합니다. 현재 사업·보관 사업의 정책을 새 자금 방식으로 전환하되 과거 원본 기록은 덮어쓰지 않습니다. 화면과 매출 전망·CSV는 권장액과 집행 상한을 구분합니다.

### 검색광고 상품 구분 (현재)

- `search`: 일반 키워드 SA. 기본 CPC는 B2C 5,000원 / B2B·B2B2C·B2G 20,000원. 탐색 키워드는 ×0.7, 구매 의도는 ×1입니다. 업종별 콘텐츠·전환 계수는 유지하며, 기존 해외 CPC 자료는 별도 참고 자료로 남깁니다.
- `brand-sa`: 자사명 SA. 기본 CPC는 일반 키워드의 10% (B2C 500원 / 기업 대상 2,000원). 100만 원씩 배정하지만 실제 클릭 비용만 차감합니다.
- `naver-brand`: 네이버 브랜드 검색 월 정액 300·400·500만 원 (기본 400만 원), 월 1개 계약. 유입이 없어도 계약 비용은 발생하며, 클릭형 광고의 100만 원 배정 단위와 구분합니다.
- 브랜드 검색 수요는 월초 인지도 20 미만이면 0, 이후 `floor(2 × (인지도 − 20)^2 + 고객 수 × 0.5)`입니다. 두 브랜드 상품이 같은 수요를 비례 배분하며, 정액 패키지는 60/80/100%의 도달 범위를 가정합니다. 검색 수요·단가·패키지 범위는 수업을 위한 게임 설정이며 실제 시장 평균이나 견적이 아닙니다.
- 세 검색 상품 모두 SA 인지도 보너스·콘텐츠 기반 전환 제약을 적용하며 DA 소재 감쇠는 적용하지 않습니다. 자사명/일반 키워드 운영은 일반 역량 기준 월 2시간, 브랜드 검색 영역 운영은 월 6시간입니다.
- [네이버 공식 과금 안내](https://ads.naver.com/help/faq/1006): 실제 브랜드 검색은 정액 계약이며 상품 유형·키워드 검색량·계약 기간에 따라 금액이 달라집니다. 게임의 월 300–500만 원과 공식 요율을 구분합니다.
- 잔여 자금 0원인 미래 월에 저장된 신규 계획은 매출 전망에서도 실행하지 않습니다. 기존 구독·이월 작업·자연 매출만 계산하고, 이후 월의 사용 가능 자금에 반영합니다.

### 전체 블로그 200편과 자연 유입 유지 (현재)

- 온드블로그 소요 시간은 **일반 역량 편당 4시간 유지**입니다.
- 기업의 모든 상품에 걸쳐 온드·체험단·기자단·파워블로그·블로그 시딩 발행을 합산합니다. 월초 누적 200편부터 블로그 자연 유입이 열립니다. 해당 월 발행으로 200편에 도달하면 다음 달부터 적용됩니다. SNS·카페·인플루언서·광고 소재는 블로그 누적에서 제외합니다.
- 유료 블로그는 당월 노출 유입을 만들면서 다음 달 검색 자산도 남깁니다. 글당 기본 자산은 온드 1 / 체험단 0.65 / 기자단 0.35 / 파워블로그 1.2 / 시딩 0.25이며 역량·집중 감쇠를 적용합니다. 검색 자산은 월 4% 감소합니다. 유료 블로그의 당월 노출은 200편 조건 전에도 발생하며 자연 유입과 분리합니다.
- 블로그 자연 검색·발견 유입자의 20%를 `memory.blogAudience` 재방문 기반으로 적립합니다. 기존 기반은 월 90% 유지하고 정수 방문을 계산합니다. 재방문 자체는 다시 신규 적립하지 않습니다. 광고·SNS·다른 유입은 이 기반에 쌓이지 않습니다. 이 수치는 교육용 가정입니다.
- 마케팅 중단 후에도 축적된 검색 자산과 재방문 기반은 남아 점차 줄어들며 자연 매출을 만들 수 있습니다. SA·DA 등 광고 방문은 당월 집행이 없으면 즉시 0이며 광고 방문을 다음 달로 이월하지 않습니다.
- 새 필드는 기존 브라우저 저장과 호환하며 미존재 시 재방문 기반 0으로 시작합니다. 기존 실행 기록은 유지하고, 새 실행·전망·과거 월 수정 이후 재계산부터 적용합니다. 상세 전망과 CSV에서 전체 블로그 합계, 자연 신규 유입과 재방문을 따로 확인합니다.
